# 3.4.8

*Released 3 June 2026*

# THE GOAT — v3.4.8

_Release date: 2026-06-03_

## Highlights

ASK THE GOAT can now run distance-constrained availability searches. "Find me
riggers within 20 km of the Forum" or "who's available near postcode 3220" now
work conversationally — completing the final acceptance criterion of the 3.4.7
geo-search feature. The Crew Finder UI gained distance filtering in 3.4.7; this
brings the same capability to the assistant.

No new data, endpoints, or third-party services: the GOAT tool reuses the
postcode-centroid table and helpers shipped in 3.4.7.

## What's new

- **`search_availability` tool gains `radius_km` and `near` parameters.**
  `radius_km` switches on the distance filter; `near` is the origin — a 4-digit
  AU postcode or a known venue name/code (e.g. "Forum", "GMHBA"). If `near` is
  omitted while `radius_km` is set, the origin defaults to the venue of the
  first call being searched.
- **Same conventions as `/api/availability`.** Each available crew member
  carries a `distance_km`; crew beyond the radius are listed under `skipped`
  with their distance (e.g. "Jordan Lee (42 km away)"); crew with no usable
  postcode are bucketed under a new `location_unknown` list and surfaced —
  never silently dropped.
- **System prompt updated** so the GOAT recognises "near" / "within N km"
  phrasing, reaches for the filter, and mentions anyone whose location is
  unknown rather than omitting them.

## Back-compatibility

Omitting `radius_km` leaves `search_availability` byte-for-byte unchanged, so
every existing GOAT availability query behaves exactly as before.

## Known limitation

The GOAT's `search_availability` still caps at the first 50 crew
(`all_crew[:50]`) for response speed — a pre-existing limit, now also bounding
the distance path. On a large roster a nearby crew member past position 50 can
be missed. The Crew Finder UI path has no such cap. Fine for the current crew
size; revisit if it bites.

## Deployment dependency

Unchanged from 3.4.7: distance results depend on crew postcodes, which come
from the postcode-enabled `list-crew-bulk.php` on production SmartStaff. That
was deployed for 3.4.7, so there is no new server-side dependency for 3.4.8. If
that PHP were ever rolled back, the GOAT would bucket everyone as
`location_unknown` — the same failure mode as the UI.

## Code changes

- `app.py`: `search_availability` tool schema (+`radius_km`, +`near`); geo
  filter in the tool handler (origin resolution, per-crew distance gate,
  `location_unknown` bucket, `distance_km` on available crew, `origin_label` in
  the response); GOAT system-prompt guidance; `APP_VERSION` -> 3.4.8.
- `version.json`: bumped to 3.4.8.

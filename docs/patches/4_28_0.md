# 4.28.0

*Released 8 August 2026*

## Schedule — calls awaiting re-confirm no longer show as green

A call whose confirmed crew count meets its requirement has always rendered
green in the Schedule. That's true numerically, but it can be wrong
operationally: if some of those confirmed crew are carrying an unanswered
re-confirm — after a timing change, or a promotion off standby — the call still
needs chasing, and green said it didn't.

Those calls now render **amber-bordered** instead: the green tint stays, because
the count genuinely is met, but the border and text switch to amber to say
"still needs follow-up".

### What you'll see

- Affected call blocks show an amber border in both the collapsed booking row
  and the expanded per-call view.
- The booking summary line reads "2 awaiting re-confirm" alongside the usual
  full / partial / empty counts.
- Hovering a block shows ⏳ and the number of crew who haven't answered.
- New legend entry: **Awaiting re-confirm**.

### Notes

- Only calls that would otherwise be **green** are affected. Partial,
  over-booked and empty calls keep their existing colours — they're already
  flagged for attention.
- Clash and warning highlighting still takes precedence, as before.
- The "Open" filter is unchanged: an awaiting call has all the crew it needs,
  so it doesn't appear there.

### Under the hood

`get-calls-bulk.php` now returns an `awaiting` count per call, derived from
pending `call_change_ack` and unacknowledged `call_promo_ack` rows. The
production endpoint is already deployed — no action needed.

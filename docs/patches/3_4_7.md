# 3.4.7

*Released 2 June 2026*

# THE GOAT — v3.4.7

_Release date: 2026-06-03_

## Highlights

Crew Finder can now filter available crew by **distance**. When filling open
slots you can limit the results to crew living within a set radius of either
the call's venue or a postcode you type in — so a Geelong load-in surfaces
Geelong crew first, not someone driving down from Craigieburn.

The crew cache also now **refreshes itself**: once on login and then every 15
minutes in the background, so the roster, ratings, groups, and inductions stay
current without anyone clicking Refresh.

Verified end-to-end against the SmartStaff test environment: venue origin,
typed-postcode origin, and the unchanged no-filter path all behave as expected,
with crew distances matching real-world geography.

## Distance / radius search

- **"Filter by distance" toggle** in the Crew Finder sidebar, under the rating
  slider. Off by default — when off, search behaves exactly as before (no
  change to existing workflow).
- **Radius slider** (5–100 km, default 25) and an **Origin** selector with two
  modes: **Venue** (anchors to the selected call's venue) or **Postcode** (type
  any 4-digit AU postcode).
- **Distance column** in the results table showing each crew member's straight-
  line km from the origin, plus a caption ("Within 25 km of Forum (3000)").
- **"Location unknown" section** — crew with a missing or unrecognised postcode
  are listed separately and counted in the header, never silently dropped.
- **Clear error messages** when an origin can't be resolved: a venue-less call
  says "No venue has been specified for this event — switch Origin to Postcode";
  an unmapped venue names itself; a bad postcode prompts for a valid 4-digit
  code.

## Cache auto-refresh

- **Refresh on login.** A full cache rebuild kicks off in the background the
  moment you log in — non-blocking, so the dashboard still loads instantly; the
  fresh data lands a couple of seconds later.
- **Recurring refresh every 15 minutes** while anyone is logged in, mirroring
  the existing session-keepalive thread. Skips cycles entirely when nobody is
  logged in, so it never polls SmartStaff for no reason.
- Interval is a single constant (`CACHE_AUTOREFRESH_SECONDS`) for easy tuning.

## Architectural notes

- **Postcode-level distances, no external geocoder.** Distances come from a
  committed AU postcode → centroid table (`au_postcodes.json`, ~3,000 postcodes)
  plus a hand-built venue → postcode map, using straight-line (Haversine)
  distance. No third-party geocoding API, no per-search network calls.
- **Venue matching handles both forms.** The dashboard tags calls with either
  the full induction name ("Festival Hall") or a short code ("Forum", "JCA",
  "MCA"); `venue_to_coords` now resolves both.
- **Refresh logic is single-source-of-truth.** The manual Refresh button, the
  on-login trigger, and the 15-minute timer all call one function and share one
  "already running" guard, so overlapping triggers can never start two
  refreshes at once.
- **Back-compatible by design.** Omitting the radius parameter leaves the
  availability API byte-for-byte unchanged, so nothing downstream is affected
  when distance filtering isn't in use.

## Deployment dependency

The updated `list-crew-bulk.php` (which adds the `postcode` field to the crew
roster) must be in place on **production** SmartStaff at `/ajax/crew/` before
this release is distributed. Without it, distance search will bucket every crew
member as "location unknown" against the live server. The packaged
`au_postcodes.json` is bundled into the app automatically by `build_dmg.sh`.

## Code changes

- `app.py`: distance helpers (`postcode_to_coords`, `haversine_km`,
  `venue_to_coords`, `resolve_origin`), `/api/availability` geo-filter, venue
  short-code matching, friendlier origin errors, cache refresh-on-login and
  15-minute auto-refresh thread, version bump to 3.4.7.
- `templates/index.html`: distance toggle, radius slider, origin selector,
  distance column, location-unknown section and header count.
- `au_postcodes.json`: new committed AU postcode centroid table.
- `build_dmg.sh`: bundles `au_postcodes.json` into `Contents/MacOS/` with a
  build-abort guard if it's missing.
- `list-crew-bulk.php`: adds `postcode` to the crew roster SELECT and payload.

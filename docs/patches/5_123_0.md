# 5.123.0

*Released 25 November 2026*

A SmartStaff outage no longer looks like a crash or a logout.

Until now, if SmartStaff couldn't be reached — the Mac off Wi-Fi, the box down, the network dropping out — almost every click in THE GOAT ended in a blank error after about twenty seconds. Behind that, the app was asking SmartStaff "am I still logged in?", getting no answer at all, deciding the session must have expired, and then trying to log in again to a box that wasn't there.

Both halves of that are now fixed. When nothing can be reached, the screen says so: **Couldn't reach SmartStaff — nothing was changed. Try again in a minute.** You find out in about ten seconds instead of twenty, no second login is attempted, and your session is left exactly as it was — the moment SmartStaff answers again everything carries on, with no logging back in and no re-entering your password.

A SmartStaff that is merely slow is treated differently, and that matters on a bad day: if the check gets as far as SmartStaff but the answer doesn't come back in time, your click carries on with the session you already have instead of stopping to log in again. If the work itself then fails, it says so in its own words.

The login screen says it too. Signing in while SmartStaff can't be reached used to end in a blank browser error page with no form and nothing to read; it now comes back to the login box with the same message, exactly as a wrong password does.

The session toast tells the truth as well. A SmartStaff that can't be reached now reads **Can't reach SmartStaff — retrying**, not "session expired — reconnecting", which was never what had happened.

Finish setup and Convert now show SmartStaff's own message rather than a bare error code, and the Unfilled Calls panel says it couldn't read the calls instead of showing an empty list, which looked like a quiet all-clear.

On the System tab, the Session checks section has a new **Failed checks** card: checks that got no answer, timeouts included. The **Check failed** re-login card beside it should now sit at zero — a failed check no longer causes a re-login at all, which was the point.

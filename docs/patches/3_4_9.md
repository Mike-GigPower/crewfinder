# 3.4.9

*Released 3 June 2026*

# THE GOAT — v3.4.9

_Release date: 2026-06-03_

## Highlights

The Crew Finder "Unfilled Calls" panel now lists only calls that still need
crew. Fully-booked calls (1/1, 12/12, 14/14 …) had been showing up alongside
genuinely unfilled ones — making the panel noisier than it should be and
inviting clicks on calls with nothing left to fill.

## The fix

- **Filter on the existing `unfilled` flag.** `scrape_calls` already tags every
  call with `unfilled = booked < required`, but `loadCalls` rendered the entire
  dashboard scrape regardless of that flag. A one-line guard in the booking-map
  build now skips any call where `booked >= required`, so only calls that need
  crew reach the list.
- **Empty-state guard after filtering.** When every call on the dashboard is
  fully booked, the panel now shows "No unfilled calls on dashboard" rather than
  rendering empty booking-group headers.

Front-end only — no backend, endpoint, or config change. The dashboard scrape
remains the data source; nothing about how `booked`/`required` are read changed.

## Known interaction

The filter drops fully-booked calls from the Crew Finder list entirely, so the
3.4.6 schedule-clash "jump to Crew Finder" path can no longer land on a call
that happens to be fully booked — its card is no longer in the list, and the
jump's retry loop times out silently. If that path needs to reach filled calls
(e.g. to swap out a clashing crew member on a 4/4 call), the alternative is to
render filled cards hidden rather than dropping them. Deferred pending whether
it bites in practice.

## Code changes

- `templates/index.html`: `loadCalls` — skip `!c.unfilled` calls when building
  the booking map; add a post-filter empty-state guard before the render.
- `app.py`: `APP_VERSION` -> 3.4.9.
- `version.json`: bumped to 3.4.9.
